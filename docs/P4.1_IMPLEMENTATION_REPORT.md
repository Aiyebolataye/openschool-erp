## E. Runtime defects found and fixed this gate (People-5 / shared infra)

1. `applicants.controller.ts`: accept/reject returned 201 (Nest default for
   POST) vs repo 200 convention -> added `@HttpCode(HttpStatus.OK)` on both.
2. `people-merge.controller.ts`: `@Permissions('people:person:merge')` was
   CLASS-level, but `PermissionGuard` reads handler (method) metadata only ->
   the guard was dead and merge endpoints were open to any authenticated
   user (verified: teacher got 200). Moved to METHOD level on all 3 routes
   (suggestions/merge/history) + `@HttpCode(OK)` on POST. DB-verified the
   permission is granted to exactly the 5 admin roles (INSTITUTION_ADMIN,
   ORG_ADMIN, PLATFORM_ADMIN, PRIMARY_INSTITUTION_ADMIN, PRINCIPAL);
   teacher/officer now 403 (e2e proven).
3. Institutions lifecycle POSTs: `@HttpCode(OK)` applied per convention.
